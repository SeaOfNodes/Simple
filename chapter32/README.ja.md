# 第32章：コンパイラ内部の高速化

[English](README.md) | 日本語

[前の章：第31章 — 描画、時間、グラフィカルゲーム](../chapter31/README.ja.md)

[次の章：第33章](../chapter33/README.ja.md)

第31章は描画、ゲーム、ライブラリを完成させたスナップショットです。
この章では言語と実行例を引き継ぎ、コンパイルとテストにかかる時間を調べます。

主な変更は次のとおりです。

- テストを独立した JVM のグループに分割し、各 JVM の JIT・GC スレッド数を調整します。
  ネイティブテストの出力先を分離し、型の格子テストも4つの JVM に分割します。
- `isConstant` と `isFinal` はポインタの参照先を再帰的にたどらないため、不要な再帰処理の準備と後始末を取り除きます。
- 高価な検証の既定値を log 8 から log 10 に変更し、インライン化の各途中段階で繰り返していたスケジュール検証を削減します。
- 外部状態を読む依存関係を不透明な引数に限定し、定数引数の削除による無関係な利用側への通知を減らします。
  呼び出しの切り離しで変更したパラメータは明示的に再処理します。
- IFG の live-out マップと作業領域を関数ごとに持ち、スピルによる再試行の間だけ再利用します。
  過去のコンパイルの基本ブロックを保持し続けることがなくなります。
  スピル候補の評価に使う関数の大きさも、彩色の試行ごとに一度だけ計算します。
- ロードを命令に組み込めるか調べる走査では、訪問済みノードを ID の BitSet で管理します。
  パック値のヒストグラムはコメントアウトし、通常のコンパイルでは収集しません。
  ELF の `.simple` セクションのサイズと内訳も測定し、今後の形式改善の基準にします。

測定ではワークリストからの peephole 呼び出しが約446万回から370万回へ、17.2%減少しました。
詳細な測定条件、実装の説明、残る調査対象は[英語版](README.md)を参照してください。

`chapter32` ディレクトリから実行します。

```sh
make -j 8 release
make -j 8 tests_nographics
make test CLASS=EscapeFlowTest "TEST_JAVA_OPTS=-XX:ActiveProcessorCount=2 -Dsimple.assert.expensive=1"
```

依存関係がない新しい環境では、オンラインで `make libs` を一度実行してください。
通常のビルドとテストはオフラインで動作し、画面や音声デバイスを必要としません。
log 1 は進捗のたびに検証し、log 8 は以前の頻度、log 0 は高価な検証だけを無効にします。
